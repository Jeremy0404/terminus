# Sources

- Kent Beck, "Canon TDD" — test list, one test at a time, make it pass, optionally refactor, repeat; and the mistakes to avoid (deleting assertions, copying computed values into expectations, mixing refactoring into making a test pass, abstracting too soon): https://newsletter.kentbeck.com/p/canon-tdd
- Martin Fowler, "Test Driven Development": https://martinfowler.com/bliki/TestDrivenDevelopment.html
- Claude Code best practices — "Give Claude a way to verify its work": address root causes rather than suppressing errors, and show evidence rather than asserting success: https://code.claude.com/docs/en/best-practices
