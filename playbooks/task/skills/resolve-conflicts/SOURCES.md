# Sources

- git-merge documentation, "How to resolve conflicts" — edit the files into shape, `git add` them, conclude with `git commit` or `git merge --continue`; inspect with `git log --merge -p <path>` and `git show :1:`/`:2:`/`:3:<path>` (common ancestor, HEAD, MERGE_HEAD): https://git-scm.com/docs/git-merge#_how_to_resolve_conflicts
- Google engineering practices, "Small CLs" — keep a change to one self-contained thing (no refactoring mixed into the merge): https://google.github.io/eng-practices/review/developer/small-cls.html
