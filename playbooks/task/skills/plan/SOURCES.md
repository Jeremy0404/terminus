# Sources

- Claude Code best practices — "Explore first, then plan, then code", and skip the plan when the diff fits in one sentence: https://code.claude.com/docs/en/best-practices
- Kent Beck, "Canon TDD" — start from a test list of behaviours, without mixing in implementation design decisions: https://newsletter.kentbeck.com/p/canon-tdd
- Google engineering practices, "Small CLs" — one self-contained change; split vertically; keep refactorings separate from feature changes: https://google.github.io/eng-practices/review/developer/small-cls.html
